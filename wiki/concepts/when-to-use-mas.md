# 什麼時候該用 MAS？

## 判斷順序（綜合 S1、S6、S2）
1. **一次 LLM 呼叫 + 檢索夠不夠？** 夠就停在這裡 [S1]。
2. **需要 agent 嗎？** 有細緻判斷、難維護的規則、大量非結構化資料才需要 [S6]。
3. **單一 agent 用到極致了嗎？** 先最大化單一 agent [S6]。
4. **出現拆分訊號？** prompt 條件分支太多、工具相似到選錯 [S6]；或 context 難管理、需要不同專長 [S5]。
5. **任務可以平行、而且價值夠高？** 才值得多代理 [S2]。

## 適合 MAS 的任務 [S2]
- 高價值、可大量平行的任務。
- 資訊量超過單一 context window。
- 需要很多複雜工具。
- 例：研究型問題（找出很多公司董事會成員這類廣度優先查詢）[S2]。

## 不適合 MAS 的任務
- 需要所有 agent 共享同一份 context、彼此依賴多的任務；多數寫程式任務屬此類 [S2]。
- 平行 agent 容易因隱含假設衝突而產出不一致的結果 [S3]。

## 一句話 [推論]
> 「先單一，後多個；能平行、夠值錢、context 放不下，才組隊。」
