# MAS 失敗模式（MAST）

MAST（Multi-Agent System Failure Taxonomy）分析 7 個框架、找出 14 種失敗模式、分成 3 大類 [S4]。失敗率約 41% 到 86.7% [S4]。

## FC1 系統設計問題（約 44%）[S4]
| 模式 | 比例 |
|---|---|
| 違反任務規格 | 11.8% |
| 違反角色規格 | 1.5% |
| 步驟重複 | 15.7% |
| 遺失對話歷史 | 2.8% |
| 不知道終止條件 | 12.4% |

## FC2 Agent 間不對齊（約 32%）[S4]
| 模式 | 比例 |
|---|---|
| 對話重置 | 2.2% |
| 沒有要求澄清 | 6.8% |
| 任務偏離 | 7.4% |
| 資訊隱藏（沒把該講的告訴別人） | 0.85% |
| 忽略其他 agent 的輸入 | 1.9% |
| 推理與行動不一致 | 13.2% |

## FC3 任務驗證（約 24%）[S4]
| 模式 | 比例 |
|---|---|
| 過早結束 | 6.2% |
| 沒驗證或驗證不完整 | 8.2% |
| 驗證錯誤 | 9.1% |

## 業界案例對照
- Anthropic 早期也遇到：簡單問題派出幾十個 subagent、一直找不存在的資料、subagent 互相干擾 [S2]。（對應步驟重複、終止條件問題 [推論]）

## 怎麼改善 [S4]
- 很多失敗來自系統設計；同一模型配更好的設計就能進步 [S4]。
- ChatDev 改善角色規格 → 成功率約 +9.4%；加入高層目標驗證 → 最多 +15.6% [S4]。
- 驗證不要只做表面檢查（如能否編譯），要多層、檢查高層目標 [S4]。見 [[verification-and-evaluation]]。
